## Bug Reports

### BUG-001: Дублікат X блокує запуск алгоритму

| Поле | Опис |
|---|---|
| **ID** | BUG-001 |
| **Назва** | Дублікат значення X є жорсткою помилкою валідації замість попередження |
| **Версія** | 1.0.0 |
| **Файл** | `js/validator.js`, рядки 46–51 |
| **Ступінь критичності** | Висока |
| **Статус** | Виправлено у v1.1.0 |
| **Кроки відтворення** | 1. Ввести дані з повторюваним x: `1,2` / `1,5` / `3,6` <br> 2. Натиснути «Запустити» |
| **Фактична поведінка** | Валідація повертає `valid: false`, алгоритм не запускається. Повідомлення: «повторюване значення x = 1 (рекомендується унікальний x)» |
| **Очікувана поведінка** | Якщо повідомлення говорить «рекомендується», то це попередження — алгоритм повинен запускатися. Генетичний алгоритм математично коректно обробляє дублікати x (MSE усереднює всі точки) |
| **Причина** | Повідомлення використовує слово «рекомендується», але помилка додається до масиву `errors`, що блокує виконання. Суперечність між повідомленням та поведінкою |
| **Виправлення** | Замінити `errors.push(...)` на `warn(...)` без додавання до `errors`. Точка все одно додається до `points`. Валідація пропускає виконання |

### BUG-002: Версія у файлі results.txt завжди «v1.0.0»

| Поле | Опис |
|---|---|
| **ID** | BUG-002 |
| **Назва** | Версія програми хардкодована в заголовку results.txt |
| **Версія** | 1.0.0 |
| **Файл** | `js/fileHandler.js`, рядок 94 |
| **Ступінь критичності** | Середня |
| **Статус** | Виправлено у v1.1.0 |
| **Кроки відтворення** | 1. Змінити `"version"` у `config.json` на будь-яке інше значення <br> 2. Виконати апроксимацію <br> 3. Натиснути «Зберегти результати» → відкрити `results.txt` |
| **Фактична поведінка** | Останній рядок `results.txt` завжди містить `Сформовано: Апроксимація функцій v1.0.0` |
| **Очікувана поведінка** | Версія у звіті відповідає поточній версії з `config.json` |
| **Причина** | Рядок hardcoded: `'  Сформовано: Апроксимація функцій v1.0.0'` не використовує конфіг |
| **Виправлення** | `downloadResults(data, version = '1.0.0')` — версія передається як параметр; `app.js` передає `getConfig('version', '1.0.0')`; рядок footer: `` `Сформовано: Апроксимація функцій v${version}` `` |

### BUG-003 (додатковий): `_evalPoly` у fileHandler.js використовує менш стабільний алгоритм

| Поле | Опис |
|---|---|
| **ID** | BUG-003 |
| **Назва** | Числова нестабільність у підрахунку похибок при генерації results.txt |
| **Версія** | 1.0.0 |
| **Файл** | `js/fileHandler.js`, рядки 164–170 |
| **Ступінь критичності** | Низька |
| **Статус** | Виправлено у v1.1.0 |
| **Кроки відтворення** | Виконати апроксимацію полінома ступеня ≥ 7 з великими значеннями x (наприклад, x > 100); зберегти results.txt — порівняти «Похибка» з тим, що показує UI |
| **Фактична поведінка** | При великому ступені полінома та великих x значення похибок у results.txt можуть незначно відрізнятися від значень в UI через використання `Math.pow` замість схеми Горнера |
| **Очікувана поведінка** | Однаковий алгоритм обчислення полінома скрізь (genetic.js, chartRenderer.js, fileHandler.js) |
| **Причина** | Два різних алгоритми: `genetic.js` і `chartRenderer.js` — схема Горнера; `fileHandler._evalPoly` — пряма сума з `Math.pow` |
| **Виправлення** | Замінити `fileHandler._evalPoly` на схему Горнера (ідентично до `genetic.js`) |
